# 16. 新增工厂类型的推荐步骤

新增工厂族时，先在 `MeMekanismMachine` 声明 base machine、tier、machine type 和正确的 `CompatMachineFamily`，再由 `CompatMachineCatalog` 生成 spec。不要为每台 tier 添加公共注册分支。

1. 确认上游真实 namespace/path、tier ID 和 machine type ID。
2. 将所有 tier 放入 `CompatFactoryTierGraph` 可索引的唯一坐标；升级链不要复制字符串 switch。
3. 在对应 provider 的 family adapter 中绑定工厂 BlockEntity、BlockType、Grid host 和 menu。
4. 工厂实现 `MeFactoryIoOwner`，声明自动均分主输入、extra/catalyst lane、输出端口和能量适配。
5. 对自定义类型只保留 provider/compat 内对第三方静态类型的适配；公共代码不依赖第三方类。
6. 安装器先按完整 `sourceBlockId`，必要时再由 provider resolver 读取 BlockState；不要恢复 nullable factory-type alias API。
7. 用 catalog/profile 运行 datagen；只为特殊透明层、LED 或 display transform 保留手写模型。
8. 主 JEI 插件只通过 `OptionalJeiCompat` 延迟注册 optional recipe viewer 类型。
9. 用 `CompatFactoryTierGraphTest`、catalog/provider boundary test、datagen test 覆盖整条 tier 链。
10. 游戏内验证 base -> basic -> next tier、跨附属升级、AE pattern I/O、输出背压和旧 NBT。

## 当前扩展等级链

EvolvedMekanism 与 EvolvedMekanism Extras 的 tier 链、Mekanism Extras 风格 tier 链以及 MekMM 组合链都以 `tierId + machineTypeId + provider/route` 区分。`absolute` 与 `absolute_overclocked`、`infinite` 与 `infinite_multiversal` 不得混用；真实来源 ID 以 catalog spec 为准。

工厂中文等级对照仍按现有资源和 lang 文件维护：`basic/advanced/elite/ultimate`、`overclocked/quantum/dense/multiversal`、`absolute/supreme/cosmic/infinite` 以及 `absolute_overclocked/supreme_quantum/cosmic_dense/infinite_multiversal`。
