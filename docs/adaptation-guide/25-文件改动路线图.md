# 25. 文件改动路线图

新增普通机器或工厂时，按下面顺序处理：

```text
MeMekanismMachine.java + CompatMachineFamily
-> CompatMachineCatalog / requirement / side-config profile
-> BlockEntity + MePatternIoOwner/MeFactoryIoOwner
-> MeInputLayout + MeOutputPort adapter
-> compat/provider/<modid> family adapter（如需）
-> client/compat/provider、client/jei/compat（如需）
-> CompatFactoryTierGraph / installer（如需）
-> runData 生成资源
-> tests、guide、客户端验证
```

公共 `ModBlocks`、`ModBlockEntities`、`ModBlockTypes`、`ModMenuTypes`、`ClientSetup` 和 installer 不为每台机器增加分散分支；它们只消费 catalog/provider 边界。

新增可选模组时，先在 `OptionalCompatClasses` 增加能力 probe，再声明 catalog requirement 和 family/provider。第三方 class 只出现在对应 compat/provider/client provider 中。

完成后运行 `runData`、`compileJava`、`test`、`build` 和 `runClient`，并检查 generated/main 没有重复资源路径。
