# 33 兼容机器目录

所有 Mekanism 及附属机器都由 `compat/catalog/CompatMachineCatalog` 提供统一描述。目录会为每个
`MeMekanismMachine` 生成唯一的 `CompatMachineSpec`，其中包含：

- 来源模组 `CompatMod`；
- 原始机器方块 ID `sourceBlockId`；
- 保持存档兼容的 ME 方块 ID `meBlockId`；
- 普通机器、工厂或高级工厂类别；
- 工厂等级和原始机器类型字符串；
- 默认侧面配置 profile；
- BlockEntity、BlockType、Grid host 和菜单共用的注册路由；
- 启用该机器所需的可选模组或功能集合。

`CompatMachineFamily` 在注册 route 之上表达真正共享实现的一族机器，例如 MekMM 普通工厂、MekMM
高级工厂、MEKE + MekMM 工厂和 EMEKE + MekAF 高级工厂。provider 使用
`CompatMachineFamilyAdapter` 为每个可用 family 绑定注册、菜单和 installer 行为，不再对每台机器
重复 `switch (spec.route())`。

目录只保存本项目枚举、字符串、资源 ID 和枚举集合，不保存第三方 `Class<?>`、指向可选类的
`Supplier` 或 method reference。实际 BlockEntity、BlockType、菜单和客户端 screen 仍由各附属的
compat provider 创建，并且必须先经过模组和 class-resource 检查。

公共注册入口遍历 `CompatMachineCatalog.available()`，再通过
`CompatMachineProviders.get(spec.provider())` 取得分模组 provider。当前 provider 为：

- `MekanismMachineProvider`；
- `MekmmMachineProvider`；
- `MekeMachineProvider`；
- `EmekMachineProvider`；
- `EmekeMachineProvider`。

provider 负责 BlockEntity 构造器、BlockType/shape/attribute、Grid host、菜单、菜单选择、安装器识别、
安装器目标和等级升级。公共 `ModBlockEntities`、`ModBlockTypes`、`ModMenuTypes`、机器方块和 installer
不直接 import 任一附属 compat 类。

客户端使用独立的 `client/compat/provider` 层。`ClientSetup` 只遍历可用 client provider，具体 screen
注册只存在于对应附属的 client provider 中，因此公共服务端 provider 不会链接客户端类。

新增机器时按以下顺序处理：

1. 在 `MeMekanismMachine` 声明稳定的 base name、typed provider/route/kind、等级和机器类型；目录会把这些
   声明收敛为唯一 `CompatMachineSpec`。
2. 确认目录生成的 `sourceBlockId` 与上游真实注册 ID 相同。
3. 为机器选择正确的 `CompatSideConfigProfile`；公共方块注册不得按附属机器类型写字符串分支。
4. 在对应 machine provider 中为该 `CompatMachineFamily` 配置 adapter；同族机器不得重复 route 分派。
5. 若需要专用 screen，只在对应 client provider 中引用第三方 BlockEntity 或 GUI 类。
6. 为新 route 或新依赖功能补 `CompatMachineCatalogTest`，不得修改已有 `mekenergistics:me_*` ID。

安装器首先按完整 `sourceBlockId` 从目录反查 ME 机器；只有上游工厂无法由稳定注册 ID 唯一表达时，
才继续使用对应 compat provider 解析 BlockState 的等级和机器类型属性。
