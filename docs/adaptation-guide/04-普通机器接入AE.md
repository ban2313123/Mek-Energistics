# 4. 普通机器接入 AE 的必做项

普通配方机器应使用 `MeRecipeMachineAeSupport<T>`，并完成这些点：

1. 字段：

```java
private MeRecipeMachineAeSupport<MyBlockEntity> aeSupport;
private AeOutputMode aeOutputMode = AeOutputMode.BOTH;

@Override
public MeRecipeMachineAeSupport<MyBlockEntity> getRecipeAeSupport() {
    if (this.aeSupport == null) {
        this.aeSupport = new MeRecipeMachineAeSupport<>(this);
    }
    return this.aeSupport;
}
```

Support 必须延迟初始化，避免上游 TileEntity 构造期间访问尚未初始化的子类字段。后续代码统一通过 `getRecipeAeSupport()` 获取 support，不直接访问字段。

2. `getInitialInventory(...)` 中用 `getRecipeAeSupport().withPatternSlots(...)` 把图样槽合并到原 Mek inventory holder。

3. `getInitialEnergyContainers(...)` 中用 `MeRecipeMachineAeSupport.AeBackedEnergyContainer` 替换原 energy container，并通过 accessor 写回 Mek 私有字段。

4. `createNewCachedRecipe(...)` 中调用：

```java
return getRecipeAeSupport().wrapRecipeEnergy(
        getEnergyContainer(),
        super.createNewCachedRecipe(recipe, cacheIndex));
```

这样配方缓存看到的是本地 FE + AE 网络能量，不会只看机器本地缓存。

5. 生命周期必须创建和销毁 grid node：

```java
clearRemoved -> getRecipeAeSupport().createOnFirstTick()
setRemoved -> getRecipeAeSupport().destroyNode()
onChunkUnloaded -> getRecipeAeSupport().destroyNode()
```

6. `saveAdditional/loadAdditional` 必须保存：

- `getRecipeAeSupport().saveAeState(...)`
- `getRecipeAeSupport().loadAeState(...)`

这些入口统一保存和恢复 `AeOutputMode`、节点、优先级、终端名称、图样槽和智能批处理状态。

7. `addContainerTrackers` 必须同步 `AeOutputMode`，否则 GUI 上的 AE 输出开关客户端状态会漂。

8. `getGridNode` 和 `getActionableNode` 使用 `MeAeMachine` 的默认实现，不要在具体机器中重复实现节点访问。

9. `setOwner` 使用 `MeAeMachine` 的默认实现，保持 Mek 安全系统和 AE 节点 owner 一致。
