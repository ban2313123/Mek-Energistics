# 2. 机器事实来源：`MeMekanismMachine` 与 catalog

所有 ME 机器先加入 `src/main/java/com/beipuo/mekenergistics/common/machine/MeMekanismMachine.java`。enum 声明稳定的 base name、machine type、tier 和 `CompatMachineFamily`；它不是唯一的注册事实来源。

`CompatMachineCatalog` 会为每个 enum 生成唯一 `CompatMachineSpec`，供公共注册、安装器、JEI、资源生成和可选依赖判断使用。新增机器后必须确认：

- `registryName()` 与 `meBlockId` 保持稳定；
- `family()` 的 provider、route 和 machine kind 正确；
- `tierId()`、`machineTypeId()` 能形成唯一工厂坐标；
- `sourceBlockId` 与上游真实方块 ID 一致；
- `CompatMachineCatalogTest` 覆盖来源 ID、family 和可用性。

普通 Mek 机器仍可使用：

```java
MACHINE_NAME((FactoryType) null, "mek_machine_name", "ME Display Name")
```

Mek 原版工厂使用已有 `FactoryTier`/`FactoryType`；扩展模组工厂使用明确的 `CompatMachineFamily` 和稳定的 tier/type 字符串。不要新增 mod-id/custom-type alias 字段，也不要按字符串复制注册分派。

可选模组要求由 catalog 的 `CompatRequirement` 表达，并统一交给 `OptionalCompatClasses` 探测。不要在 enum、公共 registry 或机器 BlockEntity 中直接调用 `ModList` 或引用第三方类。

以下机器元数据仍属于 enum 的机器事实：

- `hasSecondaryItemInput()`、`hasChemicalInput()`、`hasAdvancedChemicalInput()`；
- `hasSecondaryOutput()`、`slotLayout()`、`hasRecipeLogic()`；
- `energyUsage()`、`energyStorage()`；
- `getBasicFactory()`、`getNextFactory()`（内部委托 `CompatFactoryTierGraph`）。

输入/输出的 AE 语义不写进 enum：机器在 `MePatternIoOwner`/`MeFactoryIoOwner` 中声明 `MeInputLayout` 和 `MeOutputPort`，由共同 support/router 执行。
