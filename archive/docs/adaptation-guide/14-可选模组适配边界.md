# 14. 可选模组适配边界

公共注册入口只依赖 `CompatMachineCatalog`、`CompatMachineProvider` 和 `CompatMachineClientProvider`。具体第三方类留在对应 provider/compat package；不可用的 catalog spec 不会进入 `available()`，也不会加载其 provider 路径。

推荐边界：

- `compat/catalog`: 只保存 enum、字符串、资源 ID 和 requirement/family 数据，不保存第三方 `Class<?>` 或 handler；
- `compat/provider`: 绑定服务端 BlockEntity、BlockType、Grid host、菜单和 installer resolver；
- `client/compat/provider`: 绑定可选 screen；
- `OptionalCompatClasses`: 唯一的运行时 mod-id/class-resource probe 门面；
- mixin plugin：只在 bootstrap 阶段使用 `LoadingModList` 过滤 optional accessor。

公共 `ModBlocks`、`ModItems`、`ModBlockEntities`、`ModBlockTypes`、`ModMenuTypes`、installer 和 JEI 主入口不得直接 import optional 实现，不得自行调用 `ModList`，也不得按附属模组写分支。

## 可选模组软依赖启动流程

1. `neoforge.mods.toml` 将 `mekmm`、`mekanism_extras`、`evolvedmekanism`、`emextras` 声明为 optional，并使用正确的加载顺序。
2. 在 catalog 的 `CompatRequirement` 中声明真实依赖；`CompatMachineCatalog.available()` 统一调用 `OptionalCompatClasses` 判断。
3. 公共 registry 只遍历 `available()`；不可用机器不会解析第三方类型。
4. 服务端 provider 用 family adapter 绑定实现；组合 family 只引用其真实依赖。
5. `CompatMachineClientProviders` 只加载有可用 catalog family 的 client provider。
6. `OptionalJeiCompat` 同时检查 mod probe 和 family availability，再隔离加载 JEI compat。
7. optional mixin 由 `MekEnergisticsMixinPlugin.shouldApplyMixin(...)` 按 mod id 过滤。
8. 资源由 datagen 生成；涉及 optional 输入的 recipe 保留 NeoForge mod-loaded 条件。
9. 至少验证基础依赖、基础 + MekMM、基础 + Mekanism Extras、基础 + EvolvedMekanism/EMExtras 四种组合。

排查时优先看 catalog requirement、provider family gate、client provider gate 和 mixin plugin，而不是在公共类添加临时 `ModList` 判断。
