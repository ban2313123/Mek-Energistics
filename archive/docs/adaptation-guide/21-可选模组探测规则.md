# 21. 可选模组探测规则

运行时 mod-id/class-resource 探测集中在 `OptionalCompatClasses`。其它业务代码、catalog、provider 和 JEI 主入口不得直接调用 `ModList.get()`。

```java
public static boolean hasSomeMod() {
    return ModList.get().isLoaded("some_mod");
}

public static boolean hasSomeModFactories() {
    return hasSomeMod() && hasClassResource("com/example/somemod/factory/SomeFactory.class");
}
```

catalog 将这些能力封装为 `CompatRequirement`；`CompatMachineCatalog.available()` 统一过滤机器，provider/client provider 再按 family gate 加载实现。这样某个扩展模组缺少高级 factory class 时，只跳过对应 spec，不影响主模组启动。

Mixin bootstrap 是唯一不同边界：`MekEnergisticsMixinPlugin` 可使用 `LoadingModList` 判断目标 class 是否在加载环境中，但普通运行时逻辑仍必须经过 `OptionalCompatClasses`。
