# 13. 资源文件清单

大批量、结构固定的机器资源由 `MekEnergisticsDataGenerator` 生成到
`src/generated/resources`：

- blockstate；
- 普通和 active block model；
- 通用 item model；
- 安装配方；
- loot table。

手写资源仍放在 `src/main/resources`，主要包括：

- 普通机器有特殊 parent、texture、loader 或几何的 block model；
- 离心和种植工厂中仍保留的特殊透明层、高位 LED block model；
- 离心和种植工厂，以及 `me_electrolytic_separator`、`me_isotopic_centrifuge`、
  `me_planting_station` 的自定义 item display 变换；
- 工厂 LED、透明层等供多个机器模型引用的共享模型模板；
- `src/main/resources/assets/mekenergistics/lang/en_us.json`
- `src/main/resources/assets/mekenergistics/lang/zh_cn.json`
- 如已有俄文维护，也补 `ru_ru.json`

新增或修改目录项后运行：

```powershell
.\gradlew.bat runData --no-daemon --no-problems-report
```

必须提交对应的 `src/generated/resources` 变更。连续运行两次应产生相同内容，且
`src/main/resources` 与 `src/generated/resources` 不得存在同路径资源。生成结果由
`CompatMachineGeneratedResourcesTest` 校验数量、覆盖范围和引用目标。

命名规则：

```text
enum baseName: enrichment_chamber
registryName(): me_enrichment_chamber
block id: mekenergistics:me_enrichment_chamber
translation key: block.mekenergistics.me_enrichment_chamber
```

资源提供器以 `CompatMachineCatalog` 的稳定 ID 为输入，并由 `CompatMachineResourceProfile` 集中声明
只影响资源生成的 active model、自定义 item model 和特殊工厂模型策略。不要在 provider 中分散维护
tier/type 字符串列表，也不要让资源名、enum baseName、recipe ID 三套命名各走各的；特殊手写模型
必须在 resource profile 中显式排除。
