# 4. 普通机器接入 AE 的必做项

普通配方机器使用 `MeRecipeMachineAeSupport<T>`，并让 BlockEntity 实现 `MeAeMachine`/`MePatternIoOwner`。

机器必须声明：

- `getPatternInputLayout()`：使用 `MeInputLayout.unordered(...)` 或 `MeInputLayout.lanes(...)`；
- `getPatternOutputPorts()`：列出所有实际 item、chemical、fluid 输出端口；
- 机器特有的模式、催化剂槽或 busy 约束。

Support 延迟初始化，避免上游 TileEntity 构造期间访问子类字段。`MeAeMachine` 默认实现已经委托 `getMainNode`、`pushPattern`、`isBusy`、pattern 列表、终端和 grid 访问；具体机器不得重新解析 AE key 或实现 recipe-specific `pushPattern`。

仍需接入的上游钩子：

1. `getInitialInventory(...)` 使用 `withPatternSlots(...)` 合并样板槽；
2. `getInitialEnergyContainers(...)` 使用 `AeBackedEnergyContainer`；
3. `createNewCachedRecipe(...)` 使用 `wrapRecipeEnergy(...)`；
4. `clearRemoved` 调用 `createOnFirstTick()`；
5. `setRemoved`、`onChunkUnloaded` 调用 `destroyNode()`；
6. `saveAdditional/loadAdditional` 调用 `saveAeState/loadAeState`；
7. `addContainerTrackers` 同步 `AeOutputMode` 和 smart-pattern 状态；
8. `onUpdateServer` 调用 support 的 I/O/ticker 入口，而不是逐个插入 output slot/tank。

Support 统一保存节点、优先级、终端名、pattern slots、输出模式和 smart-pattern pending 数据。事务模拟、执行和失败回滚由 `MePatternInputRouter` 完成。
