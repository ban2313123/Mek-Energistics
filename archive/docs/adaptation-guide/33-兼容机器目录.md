# 33. 兼容机器目录

所有 Mekanism 及附属机器都由 `compat/catalog/CompatMachineCatalog` 提供统一描述。目录为每个 `MeMekanismMachine` 生成唯一 `CompatMachineSpec`，其中包含：

- 来源模组、完整原始机器方块 ID和稳定 ME 方块 ID；
- `CompatMachineFamily` 派生的 provider、route、machine kind；
- 工厂 tier ID、原始 machine type ID；
- 默认 side-config profile；
- optional `CompatRequirement` 集合。

`CompatMachineFamily` 是共享实现的唯一声明。provider 通过 `CompatMachineFamilyAdapter` 为每个 family 绑定 BlockEntity、BlockType、Grid host 和 menu；provider 自身负责 installer resolver、升级和可选菜单/installer 行为。不要在 provider 中重复 `switch (spec.route())`。

目录只保存 enum、字符串、资源 ID 和集合，不保存第三方 `Class<?>`、Supplier 或 method reference。实际 optional 类由对应 provider/client provider 在 gate 通过后加载。

公共入口遍历 `CompatMachineCatalog.available()`，再通过 `CompatMachineProviders.get(spec.provider())` 取得 server provider。客户端使用 `CompatMachineClientProviders.available()`，因此公共服务端路径不会链接客户端类。

新增机器时：

1. 在 enum 声明稳定 base name、tier/type 和 family；provider、route、kind 从 family 派生；
2. 确认 `sourceBlockId` 与上游真实注册 ID 相同；
3. 选择 catalog 的 side-config profile；
4. 在对应 provider 中为 family 配置 adapter；
5. 为 owner 声明 `MeInputLayout`、输出端口和必要特殊约束；
6. 需要专用 screen/JEI 时只在 client provider/JEI compat 中引用第三方类；
7. 补 catalog/provider/tier/datagen 测试，不修改已有 `mekenergistics:me_*` ID。

安装器首先按完整 `sourceBlockId` 反查 ME 机器；只有上游工厂无法由稳定注册 ID 唯一表达时，才调用对应 provider 解析 BlockState 的等级和机器类型属性。
