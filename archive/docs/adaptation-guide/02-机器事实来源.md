# 2. 机器事实来源：`MeMekanismMachine` 与 catalog

所有 ME 机器先加入 `src/main/java/com/beipuo/mekenergistics/common/machine/MeMekanismMachine.java`。该稳定值类为普通机器声明具名常量，并用 tier/type 矩阵生成工厂身份；`name()`、`ordinal()`、`values()` 和 `valueOf()` 保持旧身份名称、序号和查找行为。它不是唯一的注册事实来源。

这是一次有意的 Java API 破坏性迁移：`MeMekanismMachine` 不再是 `enum`，生成的工厂也不再暴露 `TIER_TYPE_FACTORY` 静态字段。旧存档和注册 ID 保持兼容，但直接使用工厂 enum 常量、`EnumSet`/`EnumMap`、enum `switch` 或依赖 enum 反射语义的第三方代码必须迁移。按名称取具体工厂时使用 `valueOf("TIER_TYPE_FACTORY")`；按分类解析时使用 `FactoryTypeKey(route, machineTypeId) × tierId`。普通机器的具名静态字段仍保留。

`CompatMachineCatalog` 会为每个机器身份生成唯一 `CompatMachineSpec`，供公共注册、安装器、JEI、资源生成和可选依赖判断使用。新增机器后必须确认：

- `registryName()` 与 `meBlockId` 保持稳定；
- `family()` 的 provider、route 和 machine kind 正确；
- `tierId()`、`machineTypeId()` 能形成唯一工厂坐标；
- `sourceBlockId` 与上游真实方块 ID 一致；
- `CompatMachineCatalogTest` 覆盖来源 ID、family 和可用性。

普通 Mek 机器使用具名 `register(...)` 声明。新增工厂类型或等级时，不再添加 `TIER_TYPE_FACTORY` 字段；应扩展 `FactoryTypeSpec`、`TierSpec` 和对应 `generateFactories(...)` 矩阵。

Mek 原版工厂使用已有 `FactoryTier`/`FactoryType`；扩展模组工厂使用明确的 `CompatMachineFamily` 和稳定的 tier/type 字符串。`FactoryTypeKey(route, machineTypeId) × tierId` 是统一解析坐标。不要新增逐 tier 工厂别名、mod-id/custom-type alias 字段，也不要按字符串复制注册分派。

可选模组要求由 catalog 的 `CompatRequirement` 表达，并统一交给 `OptionalCompatClasses` 探测。不要在机器身份表、公共 registry 或机器 BlockEntity 中直接调用 `ModList` 或引用第三方类。

以下机器元数据仍属于机器身份的固有事实：

- `hasSecondaryItemInput()`、`hasChemicalInput()`、`hasAdvancedChemicalInput()`；
- `hasSecondaryOutput()`、`slotLayout()`、`hasRecipeLogic()`；
- `energyUsage()`、`energyStorage()`；
- `getBasicFactory()`、`getNextFactory()`（内部委托 `CompatFactoryTierGraph`）。

输入/输出的 AE 语义不写进机器身份表：机器在 `MePatternIoOwner`/`MeFactoryIoOwner` 中声明 `MeInputLayout` 和 `MeOutputPort`，由共同 support/router 执行。
